# 输出结构：按需使用，不机械填满

## 阶段一：给用户审核

目标：平台 / 国家站点 / 语言；产品：品牌 / 型号 / 变体。
来源路径：A 用户资料，或 B 链接候选。版本：F1。

|事实|准备采用的值与单位|来源位置|归属|状态|
|---|---|---|---|---|
|尺寸|宽×深×高，注明本体/包装|说明书文件名 pX 或完整 URL + 选中变体 + 日期|本品资料/本品跨站页/竞品候选|待确认|
|功能与限制|动作、条件、实际作用|说明书功能页或链接具体段落|同上|待确认|
|随箱配件|包含/选购/未知，分开写|包装清单或对应证据|同上|待确认|

只保留对该商品重要的字段，不预填不存在的功能。身份、材质、容量、数量、电气、兼容性、保养、安装等按品类加入；品牌/GTIN、认证和质保无依据不借用竞品。

待裁决：仅列冲突、影响主卖点或产品识别的缺口。
拟省略：缺乏依据且不影响保守文案的声明。

审核请求示例：
“以上是准备采用的产品事实 F1。请确认是否适用于你的实际销售产品；尤其是来自竞品链接的候选参数。可回复‘F1 没问题，继续’，或直接列出修改项。”

## 阶段二：竞品研究，再交付可复制文案

先使用 [竞品研究](competitor-research.md) 的比较表，逐一回答用户链接的现状、热销证据、流量词、流量情况、称赞和痛点。未知数据明确说明。随后直接编写文案，不为研究报告再增加一次审批。

按目标平台实际字段输出标题、卖点、描述及适用附加字段，避免把多个平台字段混成一套。

文案后附小表即可：

|关键词/购买顾虑|本品已确认依据|文案位置/表达|
|---|---|---|
|实际调研所得|事实 ID 或表中字段|标题/卖点/描述|

校验摘要：采用的规则来源/日期、字段计数、已省略声明、尚未核实的平台规则（如有）。
优化现有文案时，补充最重要的 2–4 个修改理由；不生成没有实测依据的效果评分。

## 恢复与单一现役版本

长任务将事实表、确认版本、选中变体和未决问题维护在同一工作文件。收到更正时更新现役值并用一句话记录变更，不把相互矛盾的“当前状态”层层追加。成品引用事实版本；历史稿如有保留需求注明历史，勿重复发问。

## 阶段三：有产品图时的视觉交付

按 [图片工作流](image-workflow.md) 提供可视场景方案，并维护以下简表；详细提示词按每张独立保存或分节。

|方案|可视预览|适配场景/买家任务|平台与 Google 样本依据|喜爱/点击证据及缺口|
|---|---|---|---|---|
|A / B / C|可查看图板或生成预览，明确类型|依实际品类填写|来源链接及抽样时间|有数据才下结论|

用户选中方案：___；事实版本：___；整套图片数量及用途：___。

|图片 ID|信息任务/事实 ID|精确图片内文案|独立提示词位置|原始文件/尺寸|草稿版本/批准状态|最终 JPG/尺寸|
|---|---|---|---|---|---|---|

工作文件另记生成渠道、已授权额度（如适用，不记录密钥）、整套审核状态、需要修改的图片 ID。只有当前整套版本获批后进入最终导出。
